# Travel Pick 디자인 가이드 (DESIGN.md)

> 이 문서는 Claude Code가 Travel Pick을 구현할 때 따르는 시각 디자인 명세입니다.
> 기능 명세는 `../docs/Travel-Pick-PRD.md`(PRD v0.3)를 따르고, 이 문서는 **어떻게 보이고 느껴져야 하는지**를 정합니다.
> 화면 시안: `Travel-Pick-Design-Mockup.html` (브라우저로 열면 8개 화면을 오가며 볼 수 있습니다)
> 시안은 해외 여행 예시만 담고 있습니다. 국내 여행 표시 규칙은 6.4절 "국내 여행지 표시"를 따릅니다.

## 1. 콘셉트: Night Departure

**밤 공항의 출발 안내판과 탑승권.**
어두운 활주로 같은 바탕 위에 종이 탑승권이 놓이고, 결정과 관련된 순간에만 노을빛 오렌지가 켜집니다.

| 모티프 | 앱에서의 쓰임 |
|---|---|
| 출발 안내판(스플릿 플랩) | 후보 순위표, 공항 코드(OKA, TPE…) |
| 탑승권(보딩 패스) | 여행 프로젝트 요약, 1위 후보, 최종 결론, 비용 영수증 |
| 탑승권 절취선·반원 홈 | 주 정보와 보조 정보(점수, 선두 후보)의 구분 |
| 여권 도장 | AI 합의 수준(3/3, 2/3, 1/3) |
| 비행 경로(점선) | 결정 단계 내비게이션(ROUTE), 출발지→목적지 |
| 게이트 번호 | 단계 표시(GATE 02, GATE 06…) |

### 디자인 원칙
1. **티켓은 결정, 바탕은 맥락.** 종이(paper) 표면은 "결론이나 확정 정보"에만 씁니다. 나머지는 어두운 표면에 둡니다.
2. **오렌지는 한 화면에 한 번 크게.** sunset(#FF7A45)은 주요 행동 버튼, 1위, 현재 단계에만 씁니다. 여기저기 뿌리지 않습니다.
3. **숫자는 크게, 라벨은 작게.** 공항 코드·점수는 Bricolage 800으로 크게, 라벨은 Mono 대문자로 작게.
4. **AI는 목소리로 구분.** 세 모델은 고유 색 점과 2글자 모노그램(CL/GP/GM)으로 항상 구분하고, 색만으로 구분하지 않습니다(이름·텍스트 병기).
5. **장식은 정보가 있을 때만.** 그라데이션 배경, 글로우, 이모지, 왼쪽 굵은 테두리 카드는 쓰지 않습니다.

### 색 사용 규칙
- **후보지 색**은 후보를 추가한 순서대로 `--c1`부터 고정 배정합니다. 순위가 바뀌어도 색은 바뀌지 않습니다.
- **평가 기준 색**은 화려한 색을 쓰지 않고 `--k1~--k7` 톤 단계를 씁니다(후보지 색과 겹치지 않게). 가중치가 큰 기준일수록 밝습니다. 가중치가 바뀌면 순서를 다시 매깁니다.
- 어떤 색 구분이든 **라벨·텍스트를 함께** 표시합니다.
- 종이 위에서는 `--sunset` 대신 `--sunset-ink`, 모델 색은 `-ink` 버전을 씁니다(대비 확보).

## 5. 레이아웃

### 5.1 앱 셸
```
┌──────────────┬───────────────────────────────────────────┐
│ RouteNav     │  main (padding 28px clamp(16px,3vw,44px)) │
│ 260px        │  ─ 헤더: GATE 라벨 + H1 + 우측 행동        │
│ (flex 1 1)   │  ─ 본문: 카드 그리드 (gap 24–28)           │
│              │                                           │
└──────────────┴───────────────────────────────────────────┘
```
- 셸은 `display:flex; flex-wrap:wrap`. 사이드바 `flex: 1 1 260px`, 본문 `flex: 999 1 560px; min-width: 0`.
  → 넓은 화면에서는 나란히, 좁은 화면에서는 사이드바가 위로 쌓입니다.
- 모바일(≤ 760px)에서는 사이드바 대신 **상단 바 + 8칸 진행 막대 + 하단 고정 행동 바**를 씁니다(시안 07).
- 본문 안 2열 배치도 같은 방식(`flex-wrap` + 큰 `flex-grow` 값)으로 만들어 미디어 쿼리 없이 자연스럽게 접히게 합니다.
- 카드 그리드는 `repeat(auto-fill, minmax(300px, 1fr))`.

### 5.2 표면 계층
| 계층 | 바탕 | 테두리 | 반경 |
|---|---|---|---|
| 페이지 | `--night` + 점 격자 | — | — |
| 패널 카드 | `--surface` | 1px `--line` | 22 |
| 보조 카드·칩 | `--surface-2` | 1px `--line-strong` | 16–18 / 999 |
| 탑승권(결정 정보) | `--paper` | 없음 | 24 |
| 점선 안내 카드 | 투명 | 1px dashed `--line-dashed` | 22 |

그림자는 쓰지 않습니다. 깊이는 표면 색 차이와 종이/밤의 대비로만 만듭니다.

## 6. 컴포넌트 명세

### 6.1 RouteNav (사이드바 단계 내비)
- 로고: 원 안의 점선 비행 경로 + 오렌지 점(SVG, 36px) + `Travel Pick`(Bricolage 800, 22px) + `DECIDE WHERE TO GO`(Mono 10px).
- 프로젝트 전환 버튼: 프로젝트명 + `ICN · FEB · 4 PAX`(Mono). 국내는 `서울 · 가을 · 2 PAX`처럼 출발 도시를 쓰고, 시기가 미정이면 `TBD`.
- 단계 8개 `<ol>`: 각 항목 = 22px 원형 마커 + 링크(최소 높이 40px) + 우측 단계 번호(Mono).
  - 완료: `--sunset` 채움 원(체크 아이콘 선택)
  - 현재 화면: 오렌지 테두리 원 + 가운데 점, 링크 바탕 `--raised`, 흰 글자, `aria-current="page"`
  - 미완료: 1.5px `--line-dashed` 테두리 원, 글자 `#8995AE`
- 하단: AI 비용 요약 카드(이 프로젝트 누적 비용, 모델 3개 상태).

### 6.2 BoardingPass (탑승권 카드)
- 좌측 본문(`flex: 999 1 520px`) + 우측 스텁(`flex: 1 1 260px`), 사이에 2px dashed `--paper-dash`.
- 절취선 위·아래에 바탕색(`--night`) 원 2개(28px)를 절반 걸쳐 놓아 **반원 홈**을 만듭니다(카드 `overflow:hidden`).
- 본문: Mono 라벨 줄 → `ICN ─(점선 호 + 비행기)→ ? ? ?` → 4칸 정보 그리드(DEPART / DURATION / PASSENGERS / BUDGET).
  - 국내: 출발지는 한글 도시명(`서울`), 경로는 점선 호 끝에 비행기 대신 6px 원형 점.
  - 미정 값: DEPART·DURATION 칸에 `미정`(Plex KR) + 아래 Mono `TBD · AI가 추천 시기 제시`. 예산 미정은 `미정`.
  - PASSENGERS: `가족 4명` 아래 세부 형태를 `아이 동반`처럼 12px `--ink-muted`로 표시.
- 스텁: 현재 선두 코드 + 점수(`--sunset-ink`) + 장식용 바코드(`repeating-linear-gradient`, `aria-hidden`).
- 변형: 순위 1위 카드(시안 04), 최종 추천 티켓(시안 05), 모바일 티켓(가로 절취선, 시안 07).

### 6.3 DepartureBoard (후보 순위표)
- 실제 `<table>`. `border-spacing: 0 8px`로 행 사이를 띄우고, 행마다 바탕 `--surface-2`(1위는 `--surface-3`), 양 끝 셀 반경 12.
- 열: 순위(Mono) · 코드(FlapCode) · 목적지(이름 + 국가·영문) · 비행시간(Mono) · 종합 점수(숫자 + 6px 막대, 후보 색) · AI 합의(ConsensusDots) · 상태(StatusPill).
- 국내: 코드 열은 한글 지명 FlapCode, 목적지 열은 시·도, "비행" 열은 "이동"(대표 이동 수단 + 시간, 예: `KTX 1h 50m`)으로 바꿉니다.
- 좁은 화면: 표를 `overflow-x:auto` 상자에 넣고 `min-width: 640px`.

### 6.4 FlapCode (스플릿 플랩 공항 코드)
- 글자마다 `<span>` 타일: 바탕 `--night`(밤 카드 위) 또는 `--raised`, 반경 5–6, 패딩 2px 6px, JetBrains Mono 700.
- 점수가 다시 계산되어 순위가 바뀔 때 타일이 위에서 아래로 넘어가는 애니메이션(10장).

#### 국내 여행지 표시 (PRD v0.3)
국내 여행지는 공항 코드를 쓰지 않고 **한글 지명을 크게** 표시합니다. 공항 코드가 쓰이는 모든 자리(FlapCode, 탑승권, 엽서, 순위 카드, VerdictTicket, R1 의견 카드)에 같은 규칙을 적용합니다.
- 글꼴: IBM Plex Sans KR 700, 자간 −0.02em. 한글은 라틴 대문자보다 넓으므로 같은 자리의 공항 코드 크기의 **약 80%**로 줄입니다(예: 히어로 96px → 76px, 카드 54px → 44px).
- FlapCode 타일: 1~4음절 지명(제주, 강릉, 울릉도, 경주 등)은 **음절마다 타일 1개**로 나눠 플랩 모티프를 유지합니다. 5음절 이상이면 타일 없이 한 덩어리 글자로 표시합니다.
- 지명은 짧은 이름을 씁니다(예: "강원 강릉시" → `강릉`). 시·도는 부제 줄에 `강원 · KTX 1h 50m`처럼 표시합니다.
- 보조 텍스트(순위표 "목적지" 열의 영문명 등)는 국내에서는 생략합니다.
- 한 프로젝트는 국내 또는 해외 한쪽만 다루므로, 같은 화면에 공항 코드와 한글 지명이 섞이지 않습니다.

### 6.5 StatusPill / Chip
| 종류 | 스타일 |
|---|---|
| 유력 | 채움 `--sunset`, 글자 `--on-sunset`, 700 |
| 경합 | 1px `--info` 테두리, 글자 `--info` |
| 검토 | 1px `--line-dashed` 테두리, 글자 `--text-muted` |
| 필터 칩 | `--surface-3` 바탕, `--line-strong` 테두리, 13px |
| 제외 칩 | 투명, dashed 테두리 |
| 종이 위 태그 | `--paper-chip` 바탕, `--ink-2` 글자, 12px. 경고 태그는 바탕 `#F9DDD0`, 글자 `#9A3412` |

### 6.6 ConsensusDots / PassportStamp (AI 합의)
- **Dots**: 10px 원 3개, 순서 Claude → GPT → Gemini. 동의한 모델은 해당 모델 색 채움, 아니면 1.5px 테두리만. 옆에 `3/3` Mono 텍스트. `aria-label="3개 모델 중 2개 동의"`.
- **Stamp**(엽서 카드): 74px 원형 도장, 약간 회전(−14°~+11°).
  - 3/3 `CONSENSUS`: 실선 2px
  - 2/3 `MAJORITY`: 점선(dashed) 2px
  - 1/3 `SOLO PICK`: 점(dotted) 1.5px

### 6.7 ModelBadge
- 36–40px 둥근 사각형(반경 10–12), 모델별 `-bg` 바탕 + 모델 색 Mono 모노그램: `CL`, `GP`, `GM`.
- 옆에 전체 모델명. 역할 배지: `CHAIR`(의장, 오렌지 계열 테두리), `DISSENT`(소수 의견, 파랑 계열 테두리).

### 6.8 DestinationPostcard (AI 추천 엽서)
- 종이 카드. 상단 170px 일러스트 영역 + 좌하단 공항 코드(54px, 종이색) + 우상단 PassportStamp.
- 일러스트는 **이미지 없이 SVG 도형**으로: 지역 분위기별 모티프 3종.
  - 바다(sea): 해 원 + 물결 3겹
  - 도시(city): 해 원 + 빌딩 실루엣
  - 산(mountain): 해 원 + 삼각형 능선(+사원 실루엣)
  - 바탕색은 후보 색을 아주 어둡게 한 톤(예: 바다 `#13314A`, 도시 `#1F2140`), 해는 후보 색.
- 본문: 도시명(20px 700) + 국가·비행시간(국내는 시·도·이동시간) → 이유 2줄 → 태그 → 점선 구분 → ConsensusDots + 담기 버튼.
- 시기·기간이 미정이면 이유 위에 추천 시기 태그를 둡니다: 종이 위 태그 스타일로 `추천 시기 · 10월` `적정 일정 · 2박 3일`.
- 담기 버튼: 담김 = ink 채움 + 체크, 미담김 = ink 테두리 + 플러스.

### 6.9 SegmentedControl
- 바깥: `--surface-2` 바탕, 1px `--line-strong`, 반경 999, 패딩 4.
- 선택된 항목: `--paper` 바탕 + `--ink` 글자 700. 미선택: 투명 + `--text-muted`.
- `role="group"` + 각 버튼 `aria-pressed`.

### 6.10 MemberAvatar / MemberSwitcher
- 32–36px 원, 동행인 고유 색 바탕 + 이름 첫 글자. 동행인 색은 후보 팔레트 `--c1~` 순서를 재사용하되 같은 화면에 후보 색과 함께 나오면 이름을 반드시 병기합니다.
- 스위처 버튼: 선택 = 1.5px `--sunset` 테두리 + `--m-claude-bg` 계열 바탕 + `입력 중`, 나머지는 상태(`완료` 초록 Mono / `대기` 회색 Mono).

### 6.11 PairwiseSlider (AHP 쌍대비교)
- 3열 그리드 `84px | 1fr | 84px`: 왼쪽 기준명 · `<input type="range" min="-8" max="8">` · 오른쪽 기준명.
  - 값 v < 0 이면 왼쪽이 `|v|+1`배 중요, v > 0 이면 오른쪽, 0 은 같음.
  - 더 중요한 쪽 이름은 700 + `--sunset-soft`(오른쪽이 이기면 `--info`).
- 슬라이더 아래 눈금 `9 7 5 3 1 3 5 7 9`(Mono 11px, 장식 `aria-hidden`), 오른쪽 끝에 "3배 중요" 결과 문구.
- 트랙 4px `--track`, 썸 22px `--sunset` + 4px 바탕색 테두리 + 1.5px 오렌지 링. 포커스 시 `--info` 외곽선.
- **CR 경고 행**: CR ≥ 0.1이거나 가장 모순된 비교일 때 행 전체를 `--warn-bg` + `--warn-line` 테두리로 감싸고 삼각형 경고 아이콘 + 수정 제안 문장("3배로 낮추면 CR이 0.04로 좋아집니다").
- 진행 표시: `12 / 21` + 120px 진행 막대.

### 6.12 CRGauge (일관성 비율 게이지)
- 종이 카드 안 반원 게이지(SVG 240×136): 회색 트랙 + 0~0.10 구간 `--ok-ink` 호, 바늘(ink) + 중심점.
- 아래 큰 숫자(Bricolage 800, 52px) + 판정 문구(양호: `--ok-ink` / 재검토: `--sunset-ink`).
- 하단 3칸: λmax · CI · RI(n).

### 6.14 DebateRound (AI 심사 회의)
- 라운드 마커: 44px 원 + `R1/R2/R3`(Mono 700). R1·R2는 오렌지 테두리, R3(의장)은 오렌지 채움.
- **R1 의견 카드**: ModelBadge → 1위 코드(Bricolage 40px) + `2위 TPE` → 이유 → 우려(한 단계 밝은 바탕 상자).
- **R2 반박 목록**: 왼쪽에 2px dashed 세로선(비행 경로)으로 이어진 항목들. 항목 = `CL → GM`(발화 모델 색 Mono) + 문장 + 태그(반박=오렌지 계열, 보완=파랑 계열, 동의=초록 계열).
- **R3 VerdictTicket**: 큰 탑승권. 왼쪽 스텁에 `FINAL CALL · 최종 추천`, 코드 96px, 배지(`토론 후 합의 3/3`, `계산 결과와 일치`), 바코드. 오른쪽에 합의한 점 / 남은 쟁점 / **결정 전 확인 체크리스트**(`<fieldset>` + 실제 체크박스).
- 계산 결과와 AI 결론이 다르면 배지를 `계산 결과와 다름`(sunset-ink 테두리)으로 바꾸고 이유 문단을 추가합니다.

### 6.15 CostReceipt (실행 전 비용 확인 창)

- 상단: `BEFORE TAKEOFF · 실행 전 확인` + 작업명 + 호출 설명 + 닫기(44px 원형 아이콘 버튼).

- 절취선(dashed) 아래: `ESTIMATED TOTAL` + 지난 실행 예상 대비 실제 차이 + 큰 합계(Bricolage 800, 46px, `--sunset-ink`) + 원화 환산.

- 맨 아래 영수증 톱니 모양(지그재그) 가장자리.
- 체크박스를 끄면 호출 수·합계·실행 버튼 문구가 즉시 바뀝니다.

BUDGET 칸은 "1인 총경비" 입력(원 단위, 비워 두면 미정) |
| 자료 수집 (03) | 후보 탭(FlapCode) + 항목 카드 그리드. 카드 = 항목명(Mono 라벨) + 확정값(큰 글자) + 모델별 값 3줄(ModelBadge 작게) + 출처 링크. 모델 간 차이가 크면 `--warn-*` 스타일, 출처 없음은 `확인 필요` 경고 태그. 확정값 입력은 종이 바탕 |
| 점수 매기기 (05) | 후보 × 기준 행렬 표. 셀 = 최종 점수(크게) + 모델 점수 3개(작은 점·숫자). 표준편차 ≥ 2인 셀은 `--warn-bg`. 상단에 [AI 평균 적용] [직접 입력] SegmentedControl |
| 내보내기 (08) | 종이 영수증 스타일 목록: JSON 백업 / Excel / Word / PDF 각각 한 줄(아이콘 + 설명 + 버튼). 마지막 백업 시각 표시 |
| 설정 | 밤 패널 카드 목록: API 키(마스킹 입력, 저장 방식 SegmentedControl), 모델 3개(ModelBadge + 슬러그 입력 + 단가 Mono), 웹 검색 토글, 환율, 저장 공간 막대(80% 이상 `--sunset`) |

## 10. 모션
- 기본 지속 시간 200–400ms, 이징 `cubic-bezier(0.2, 0.8, 0.2, 1)`.
- **플랩 넘김**: 순위가 바뀌면 FlapCode 타일이 `rotateX`로 위→아래 넘어가며 글자가 바뀜(타일당 40ms 지연).
- **점수 숫자**: 이전 값에서 새 값으로 400ms 카운트.
- **AI 응답 도착**: 카드가 8px 아래에서 올라오며 나타남(opacity 0→1).
- **도장 찍기**: 합의 결과가 나오면 PassportStamp가 1.15배에서 1배로 줄며 찍힘(180ms).
- `prefers-reduced-motion: reduce`에서는 모든 이동·회전을 끄고 즉시 바꿉니다.

## 12. 접근성 체크리스트
- 텍스트 대비 4.5:1 이상(24px 이상 큰 글자 3:1). `--text-faint`(#7C88A3)는 12px 이상 Mono 라벨에만 씁니다.
- 모든 상호작용은 실제 `<button>`, `<a href>`, `<input>`, `<select>`, `<label>`로 만듭니다.
- 터치 영역 최소 44×44px.
- 아이콘만 있는 버튼은 `aria-label`.
- 색으로만 구분하지 않기: 합의 점에 `3/3` 텍스트, 차트에 범례 텍스트·선 모양(실선/점선) 차이.
- 차트마다 대응하는 표 또는 `aria-label` 요약.
- 포커스 링: 2px `--info` 외곽선, 오프셋 2–4px.
