# Travel Pick 개발 보고서 (v1)

- 작성일: 2026-10-14
- 버전: v1

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | Travel Pick |
| 한 줄 소개 | 세 AI(Claude Sonnet 5.5, GPT-6 Luna, Gemini 3.8 Flash)와 함께 다음 여행지를 고르는 다기준 의사결정 웹 앱 |
| 대상 사용자 | 가족·친구·연인과 여행지를 정하는 개인(1인 사용, 로그인 없음) |

## 2. 목표 및 배경

여행지를 고를 때는 비용·날씨·거리·음식·안전 같은 기준이 서로 부딪히고, 함께 가는 사람마다 중요하게 여기는 것이 다릅니다. 검색이나 AI 한 번의 답만으로는 "왜 이곳인지"를 설명하기 어렵습니다.

Travel Pick은 다음을 한 흐름으로 묶는 것을 목표로 했습니다.

- **AI는 조사와 의견을 맡고, 결정은 사람이 계산으로 확인**: 세 모델이 추천·조사·점수 초안·심사를 하지만, 최종 점수와 결정은 항상 사용자가 확정합니다.
- **교차 검증**: 같은 질문을 세 모델에 던져 공통 추천, 수치 차이, 점수 표준편차로 "AI끼리 얼마나 합의하는지"를 보여 줍니다.
- **설명 가능한 결정**: 가중합과 AHP(쌍대비교·일관성 비율), 민감도 분석, 동행인별 1위를 보여 주고, 결과를 Word·PDF 리포트로 남깁니다.
- **비용 투명성**: 모든 AI 호출 전에 예상 비용을 보여 주고, 실행 후 실제 비용을 기록합니다.

## 4. 기술 스택 및 아키텍처

| 영역 | 선택 | 이유 |
|---|---|---|
| 형태 | `index.html` + CSS + ES 모듈, **빌드 없음** | GitHub Pages에 그대로 올림. 모듈별로 나눠 테스트·관리가 쉬움(단일 HTML 대신 사용자가 분리 구조를 선택) |
| UI | Vanilla JS + `h()` DOM 도우미 + CSS 변수 | 의존성 최소화. 문자열은 항상 텍스트 노드로 넣어 XSS 방지 |
| 상태 | `createState`(update/subscribe) + 300ms 자동 저장 | 화면은 상태가 바뀔 때마다 다시 그리고, 포커스·입력 중인 글자는 id로 되살림 |
| 저장 | localStorage(`travelpick:` 접두사), API 키만 세션 선택 가능 | 서버 없는 개인용. 용량 측정·캐시 자동 정리·용량 초과 안내 |
| AI | OpenRouter Chat Completions(브라우저 직접 호출, CORS 허용) | 키 하나로 세 모델. `usage.cost`로 실제 비용 기록, web 플러그인으로 검색 |
| 차트 | Chart.js 4.5.1(지연 로딩) | 레이더·막대·선, 리포트용 PNG(`toBase64Image`) |
| Markdown | marked 12.0.2 + DOMPurify 3.1.6(지연 로딩) | AI 심사 본문을 정화한 뒤 표시 |
| 내보내기 | SheetJS 0.20.3, docx 9.5.1(버튼을 누를 때 동적 import), 인쇄 CSS | 브라우저에서 xlsx·docx 생성, PDF는 "PDF로 저장"(한글 글꼴 문제 없음) |
| 테스트 | Node 내장 `node:test` | 별도 프레임워크 없이 순수 함수·가짜 fetch·xlsx/docx 다시 읽기 검증 |
| 배포 | GitHub Pages(`main` 루트, `.nojekyll`) | 무료 HTTPS, 푸시하면 자동 배포 |

**의존 방향**: `screens → ui → selectors → core`. `js/core/`는 DOM·localStorage·fetch를 직접 쓰지 않는 순수 함수만 두고 반드시 테스트합니다.

```
js/
  core/      mcdm(AHP·가중합·민감도) · store · schema · project · weights · scores · cost · merge · research · panel
  ai/        openrouter(호출기) · json(파싱·검증·재요청) · runner(예상→확인 창→실행→기록) · prompts
  selectors.js  결과·합의 수준·자료 카드 등 화면용 계산(저장하지 않고 매번 계산)
  ui/        dom · 컴포넌트(탑승권·플랩·엽서·영수증·심사 회의·리포트) · charts · markdown · motion
  screens/   home · conditions · candidates · research · weights · scores · results · panel · export · settings
  export/    excel · word · report(리포트 데이터 한 곳) · charts(리포트 PNG)
```

**AI 호출 흐름**: 화면이 요청(프롬프트·스키마)을 만들면 `runner.planRun`이 모델별 토큰·비용을 추정하고, 비용 확인 창(CostReceipt)에서 모델을 고른 뒤 병렬 실행합니다. 응답은 JSON 스키마로 검증하고 실패하면 오류를 붙여 1회 재요청합니다. 실제 비용은 `aiRuns`에 남아 다음 예상의 출력 길이를 보정합니다. 최종 심사처럼 라운드가 이어지는 작업은 `runStaged`로 확인 창 한 번에 차례로 실행합니다.

## 6. 주요 의사결정과 이유

- **빌드 없는 ES 모듈 분리**: 단일 HTML보다 모듈 단위 테스트와 수정이 쉽고, 빌드 도구 없이도 GitHub Pages에 바로 올라갑니다.
- **한 프로젝트 = 국내 또는 해외**: 조사 항목(비자·항공 vs 이동 수단)과 표시(공항 코드 vs 한글 지명)가 달라 섞으면 비교가 어색해집니다. 후보를 담은 뒤에는 여행 종류를 잠급니다.
- **국내는 공항 코드 대신 한글 지명**: 플랩 타일을 음절마다 나눠 디자인 모티프를 유지합니다.
- **시기·기간 미정이면 AI가 후보별 추천 시기·일정**: 담을 때 `plannedPeriod`로 저장하고 자료 수집 기준으로 씁니다.
- **가중치·CR은 저장하지 않고 매번 계산**: AHP 판단은 기준 id 쌍(`a|b`)으로 저장해 기준을 추가·삭제해도 다른 판단이 밀리지 않습니다.
- **AI는 최종 점수를 바꾸지 않음**: 점수 초안은 별도 칸에 두고 사용자가 적용할 때만 최종 점수가 됩니다.
- **"계산 결과와 일치"는 앱이 판단**: AI가 준 플래그 대신 의장의 선택과 계산 1위를 직접 비교합니다.
- **비용 상한 대신 실행 전 확인 창**: 기능마다 예상 비용을 보여 주고 모델을 끌 수 있게 했습니다. 키별 한도는 OpenRouter 대시보드에서 걸도록 안내합니다.
- **리포트 데이터 한 곳(`export/report.js`)**: 미리보기·PDF·Word가 같은 데이터를 써서 내용이 어긋나지 않습니다.
- **색은 `tokens.css`에만**: 테스트가 다른 CSS·JS의 HEX 색을 막습니다. Word 파일 색도 토큰 값을 읽어 씁니다.
- **git은 사용자가 직접**: Claude는 커밋 시점과 메시지만 제안했습니다.

## 7. 문제 해결 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| AHP 고칠 쌍 제안 값이 늘 1 | 왜곡된 가중치로 제안값 계산 | 그 칸에 넣었을 때 CR이 가장 낮아지는 Saaty 값을 직접 탐색 |
| 저장 공간 191% 표시 | 바이트로 셈 | 크롬 한도가 UTF-16 글자 수(약 524만 자)임을 실측해 글자 수로 비교 |
| 입력 후 다음 칸 클릭이 사라짐 | change에서 바로 다시 그리기 | `setTimeout(0)` 뒤 저장 + `data-committed`로 입력 중 글자 이어받기 |
| 같은 버튼 노드가 두 곳에서 이동 | 노드 재사용 | 팩토리 함수로 매번 생성 |
| 테스트 시험 호출이 프로젝트 비용에 섞임 | 모든 실행을 기록 | `record: false` 옵션 |
| 조건 칩에 `0`이 보임 | `length && chip()` | `length > 0 &&` |
| 모바일 가로 스크롤 | 스크린 리더용 절대 위치 글자가 스크롤 영역을 벗어남 | 탭 줄을 `position: relative`로 |
| 종이 위 체크박스가 검게 보임 | 페이지 `color-scheme: dark` | 종이 위 체크박스만 `light` |
| 리포트 제목이 안 보임 | 밤 테마 제목 색이 종이 위에 적용 | 리포트 제목은 잉크 색 |
| Word 파일 색 HEX가 테스트에 걸림 | 색 규칙 | 토큰 값을 런타임에 읽어 전달 |
| 인쇄 시 종이색 바탕 | `print-color-adjust: exact` | 인쇄할 때 리포트 바탕 투명 |
| 접근성: 터치 영역 40px, 랜드마크 밖 요소 | 시안 치수 그대로 | 44px로 키우고 상단 바 `header`, 하단 바 `nav`, 스크롤 표 `role=region tabindex=0` |
| 화면을 다시 그릴 때마다 카드 애니메이션 반복 | 전체 다시 그리기 구조 | `ui/motion.js`가 지난 값을 기억해 바뀐 경우만 움직임 |

## 8. 보안/성능 고려사항

- **API 키**: OpenRouter 외에는 보내지 않음. JSON 백업·Excel·Word·PDF에 들어가지 않는지 테스트로 확인. "이번 세션만" 저장 선택.
- **XSS**: 모든 문자열은 텍스트 노드로. AI Markdown은 DOMPurify로 정화한 뒤에만 `innerHTML`(시험으로 넣은 `<script>`, `<img onerror>`가 제거됨을 확인). 링크는 `noopener noreferrer`.
- **개인정보**: 심사에 동행인 이름 대신 "구성원 N"을 보내는 옵션(기본 켜짐).
- **저장 공간**: 사용량 표시, 80% 경고, 캐시 자동 정리, 저장 실패 시 화면 데이터는 유지하고 안내, 공간이 생기면 다음 변경에서 함께 저장.
- **성능**: 가장 큰 경우(후보 8 × 기준 9 × 동행인 4명 AHP)에서 결과·민감도·합의 수준·리포트 데이터 계산이 모두 100ms 이내(최대 약 24ms, `tests/perf.test.js`). 첫 화면은 글꼴만 불러오고 차트·내보내기 라이브러리는 필요할 때만.
- **AI 견고성**: 시간 초과 90초, 동시 3개, 429·5xx 지수 백오프 재시도, 일부 모델 실패해도 진행, 실패분만 다시 시도.

## 9. 테스트 및 검증

## 11. 알려진 한계

- **데이터는 한 브라우저에만**: 기기 간 동기화가 없어 JSON 백업으로 옮겨야 합니다. 로컬과 배포 주소도 저장 공간이 따로입니다.
- **AI 정보의 정확성**: 웹 검색 결과에 의존하며 가격은 대략적인 범위입니다. 출처 없는 항목은 "확인 필요"로 표시하지만 사실 확인은 사용자 몫입니다.
- **비용 예상은 추정치**: 토큰 계수와 지난 실행 평균으로 계산하며, 웹 검색 결과 분량에 따라 차이가 날 수 있습니다.
- **실제 API 호출은 개발 중 가짜 응답으로 검증**: 실제 모델 출력 형식이 달라 생기는 문제는 사용하며 조정이 필요할 수 있습니다.
- **모델 슬러그·단가 변화**: 설정에서 바꿀 수 있지만 모델이 사라지면 직접 바꿔야 합니다.
- **Word 확인**: MS Word·한컴오피스에서 직접 열어 보는 확인은 아직 남아 있습니다.
- **정량 기준 자동 환산(F7-5)과 사용자 정의 조사 항목(F4-8)** 같은 P1·P2 일부는 구현하지 않았습니다.
